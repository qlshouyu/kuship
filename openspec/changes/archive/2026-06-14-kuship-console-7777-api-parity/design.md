## Context

kuship-console 已实现 37 个 Controller，覆盖鉴权/bootstrap、企业、团队、集群、应用、组件读等域，且各自在历史 change 中声称对齐 7070。7777 前端(kuship-ui，拷贝自 rainbond-ui)以 `request(`${baseUrl}/console/...`)` 调用这些端点。三服务(7070/8000/7777)当前均在线。本次以前端真实调用面为驱动做一次端到端 deep-diff 收口。

## Goals / Non-Goals

**Goals:**
- 对已实现端点逐个 deep-diff 8000 vs 7070，收口残留字段差异。
- 沉淀一份按前端导航旅程排序、可复用的逐端点校准清单与方法。
- 修正以"对齐 7070"为唯一标准，且最小化(只改差异处)。

**Non-Goals:**
- 不实现 7777 调用但 console 尚未实现(404)的端点。
- 不改既有端点 spec 的 requirement(除非 diff 揭示 spec 本身描述有误)。
- 不做 schema 变更、不引入新端点。

## Decisions

- **驱动源**:以 7777 前端导航旅程定义端点顺序与优先级,而非按 Controller 字母序——确保先收口用户首屏与主链路。
- **鉴权等价**:校准前先在 8000 与 7070 各自登录取得等价账号的 cookie/token,保证两侧处于相同鉴权态;错误路径(未认证/非法参数)同样对照。
- **稳定 vs 易变字段**:沿用 memory「7070 校准打法」与「集群 check_status 富化」经验——稳定字段值对齐,易变字段(时间戳/实时状态/运行态/资源用量)仅校形状。必要时对运行态用「region 组件 provision 配方」铺设可丢弃组件以解锁运行态读校准。
- **deep-diff 手法**:同参调用两侧,规范化(排序 key、剥离易变字段)后逐字段比对;差异分类为 缺字段/多字段/类型/默认值/顺序/msg/分页 七类。
- **修正即对齐**:差异一律改 kuship-console 向 7070 看齐;若 7070 行为本身被判定为应保留的契约,则记录并修正。
- **批次组织**:按域分组(bootstrap、企业、团队与成员/角色、集群、组件读)逐组推进,每组内逐端点 deep-diff，组结束跑该域单测。

## Risks / Trade-offs

- **易变字段误报**:实时状态/时间戳在两环境不同→以形状校验规避,但可能漏掉真实差异;通过多次采样降低风险。
- **数据前置不足**:部分端点(组件运行态、集群富化)需联调集群有真实数据;无数据时只能校空态/形状,真值对齐留待有数据时补。
- **范围蔓延**:"一个一个全部"易膨胀→本 change 限定已实现端点;404 端点显式排除为后续 feature。
- **鉴权漂移**:两侧账号权限不一致会污染 diff→校准前核对账号角色(含 viewer 低权场景)。
